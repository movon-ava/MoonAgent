## 四、建议（按性价比排序）

### P0（建议下轮做，风险低收益高）
1. **异常治理**：190 处 `except Exception` 里挑出 19 处静默 `pass`，全部改为 `logger.debug(..., exc_info=True)` 或显式白名单；再加 `ruff BLE001` + `select` 规则进 `pyproject.toml`，防止下一次静默失效。约 2 小时。
2. **测试收敛**：33 个脚本改为 pytest 用例（保留脚本入口），加 `pytest-cov` 与一个 `uv run pytest` 入口，便于 CI。约半天。

### P1（结构，收益大但需要谨慎回归）
3. **平台客户端抽象**：五个客户端重复「双 JSON 编码 POST / 重试 / 限速 / env 生命周期 / 附件下载 / 提交去重」。建议抽 `backend/platforms/base.py`（`_post_json(retries, double_encode)`、`ensure_target/stop_target`、`submit_once`），每平台只留差异映射。预计 2,903 → 约 1,500 行，约 1–2 天。
4. **面板拆分**：`scripts/webui.py` 2,153 行单文件（HTML/CSS/JS 全内联）。拆 `scripts/webui/{server.py, state.py, argv.py, assets/}`，静态资源独立文件，便于改样式与做前后端分离。约 1 天。
5. **三套协调器去重**：`deepseek_coordinator.py` / `claude_coordinator.py` / `codex_coordinator.py` 的工具集与提示词重复约 400 行，抽 `coordinator_tools.py`。约半天。

### P2（体验/安全，可选）
6. **配置单一来源**：`Settings` 字段 → CLI 选项 → 面板表单 → `.env` 四处手工同步，容易漂移（本轮 `--require-evidence` 就因命名不一致报错过）。建议用一份字段表生成 CLI 与面板控件。
7. **本地日志脱敏**：`logs/trace-*.jsonl` 含命令、响应和 flag；发布仓已脱敏，但本地明文长期留存。可选：写 trace 时对 `flag{...}`/token 做掩码。
8. **平台/系统耦合**：WSRX 与 `taskkill` 仅 Windows；若将来跑 Linux，需要 `wsrx` 的替代与 `kill -TERM` 分支。
9. **成本可视化**：余额差计费已可用，但缺「每题成本 / 每小时成本」聚合；可从 trace 的 `cost_usd` 汇总，面板加一列。
